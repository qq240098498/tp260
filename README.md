# 污染源在线监测与排污总量核算台

运维与环保岗共用的核算台：录排污单位与排放口、管在线设备、盯小时值、算日平均与总量、对许可量、出报表。

## 运行

```
npm install
npm start
```

默认端口 5260（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：单位数量与生产中数量、排放口数量与运行中数量、设备数量与各状态台数、监测数据条数与自动与补录条数、无效标记条数、手工替代登记条数（已复核/待复核）与故障/送检段数、本月缺口小时与手工替代小时、报表数量与已上报数量、超标排放口数量、年累计排放量与年许可量对照；下面按排放口一行给出本月各指标的月均值、月总量与超标情况。
- **排污单位与排放口**：单位台账（编码、名称、行业、状态、许可证号、许可年起始日）带排放口清单；排放口台账（编码、名称、所属单位、类型、状态、设备数、数据条数），两者都带增改删。
- **在线设备**：设备台账（编号、所属排放口、监测指标、型号、设备状态、校准有效期、数据条数、无效标记条数），带增改删。
- **监测数据**：小时值清单（排放口、设备、指标、时刻、数值、标记、来源、登记人、是否计入、折算后浓度、当时氧含量与流量），支持按排放口、设备、指标、来源、日期与月份筛选，带单条新增、修改与删除。来源分「自动 / 补录 / 手工替代」三类，手工替代行淡紫底、无效读数淡红底，展开可看手工采样的方法、检出限、单位、登记人、复核人与复核意见。
- **替代取证**：设备故障/送检台账（设备、原因、起止时刻、单号、送检机构、登记人）是手工数据的唯一依据；故障或送检期间可登记手工监测数据作为等效值（采样时刻、监测方法、检出限、监测单位、登记人必填，采样时刻必须落在已登记时段内），经复核人复核通过才入账。页面按口径给出每个指标的应监测/自动/补录/手工替代/无效/缺口小时数、替代占比与分来源总量，并把所有缺口时段（含超出口径被截断、改按缺口处理的手工值）显式列出。
- **核算与报表**：选定排放口与月份后给出逐日明细（计入/自动/补录/手工替代/无效/缺口小时数、日均浓度与平均口径、限值、是否超标、当日流量合计、整日不计入原因；点行展开逐小时明细，逐小时标明来源状态与不计入原因）与汇总（月均、月总量及其中自动/补录/手工替代各占多少吨、季度总量、季度许可量、年累计、手工替代与缺口小时数、超标天数与超标小时数、超标判定），并可生成与查看报表（草稿、已上报、退回），报表详情同样分来源列示总量。

## 口径（页面上的说明与数字都要与本段一致）

1. **有效小时值**：数据标记为有效、设备状态为「正常」、数值在量程（默认 0 到 500）之内，三条都满足才计入统计；设备处于校准、维护、故障状态，或者数值超量程或为负数的，按无效处理（不计入平均、总量与超标判定），页面要显式标出来。
2. **折算浓度**：`折算浓度 = 实测浓度 × (21 − 基准氧含量) / (21 − 实测氧含量)`，基准氧含量默认 8（可在设置里改）；该时刻没有氧含量读数时按基准氧处理（等价于不折算）。所有平均、总量与超标判定都用折算后的浓度。
3. **日平均**：按小时流量加权，`日均 = Σ(折算浓度 × 该小时流量) / Σ该小时流量`；单日有效小时不足（口径按 18 小时）或者补录小时超过上限（默认 6 小时）的，**该日不计入平均与总量**，页面要写明原因。
4. **补录**：允许用相邻有效值补算缺失小时，补录数据要在页面与结果里与原数据区分开；补录超过单日上限时该日按无效处理，不许把补出来的数当真实监测结果用。
5. **月总量**：`每小时排放量(吨) = 折算浓度(mg/L) × 流量(m³/h) × 1000(升每立方米) / 1e9`，月总量是逐小时按时刻配对累加（浓度与流量必须取同一时刻的那一对）；月平均按有数据且有效的天数平均（分母是有效天数，不是当月天数）。季度总量与年累计用同一套公式逐小时累加，不做任何按天外推。
6. **季度与年**：季度总量按季度内逐小时累加；季度许可量按年许可量乘以该季度实际天数占全年天数的比例分解；年累计按许可年（单位台账里的许可年起始日）累计，跨自然年不重置也不带入其他许可年的数据。
7. **超标判定**：日平均超过限值（COD 100、氨氮 15，可改）**或者**小时值超过限值达到 3 次及以上，都算这个月超标；两项都要在页面上分别给出。
8. **不计入统计的情形**：排污单位处于停产状态、或者排放口处于停用状态的时段，其小时值不计入平均与总量，也不参与超标判定（但要保留可查）。
9. **手工替代（设备故障或送检期间的等效值）**：
   - **登记依据**：先登记设备故障/送检时段（设备、原因、起止时刻），手工监测的采样时刻必须落在该时段内；没有依据时段、或采样时刻落在时段外的，一律不许入账。
   - **必填取证要素**：采样时刻、监测方法、检出限、监测单位、登记人，缺一不可；登记后为「待复核」，必须有复核人并给出「通过/驳回」结论。驳回与待复核的数据不参与任何统计；已复核入账的数据锁定，更正须先驳回。
   - **覆盖边界**：一次故障/送检的替代，自最早采样时刻起最多覆盖 `maxManualSpanHours`（默认 72 小时）；被覆盖的每个自然日至少有 `manualMinSamplesPerDay`（默认 4）次手工监测（一个样品代表采样时刻起 `24/频次` 小时，当日样品不跨下一样品）；单月替代小时数占当月应监测小时数的比例不得超过 `manualMaxCoverageRatio`（默认 25%）。以上任一条超出，对应小时**按缺口处理**，并在替代取证页与逐小时明细里标明截断原因——不许用替代数据把缺口填平还看不出来。
   - **参与核算的方式**：经复核且在边界内的手工值作为对应小时的浓度；替代期间的流量取同一时刻的有效流量（自动流量优先，其次经复核的手工流量），缺有效流量的小时不估算、不计总量并计入缺口。手工替代小时与自动、补录一样参与日均（流量加权）与逐小时总量，但在数据清单、汇总与报表里始终单独列示「自动/补录/手工替代」的小时数与吨数、复核状态与采样时段。
   - **替代日的有效性**：含手工替代的日期不走普通日 18 小时门槛，改按手工频次（默认 ≥4 次/日）判定；频次不足的整日不计入平均与总量，并写明原因。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/plants | 单位清单（支持 status、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/plants/:id | 详情（含排放口、报表）/ 修改 / 删除 |
| GET / POST | /api/outlets | 排放口清单（支持 plantId、status）/ 新增 |
| PATCH / DELETE | /api/outlets/:id | 修改 / 删除 |
| GET | /api/outlets/:id/summary?month= | 月均、月总量、季度总量与许可、年累计、超标情况、设备清单 |
| GET | /api/outlets/:id/daily?month=&metric= | 逐日明细（有效小时数、补录小时数、日均、限值、是否超标、流量合计） |
| GET | /api/outlets/:id/exceedance?month=&metric= | 超标判定（超标天数、超标小时数、小时超标是否成立、是否超标、月均） |
| GET | /api/outlets/:id/coverage?month= | 替代覆盖与缺口报告（各指标应监测/自动/补录/手工替代/无效/缺口小时、替代占比与上限、分来源总量、缺口分段及截断原因、在执行的替代口径设置） |
| GET / POST | /api/devices | 设备清单（支持 outletId、metric、status）/ 新增 |
| PATCH / DELETE | /api/devices/:id | 修改 / 删除 |
| GET / POST | /api/outages | 设备故障/送检时段清单（支持 outletId、deviceId、metric、reasonType）/ 新增（手工数据的唯一依据） |
| PATCH / DELETE | /api/outages/:id | 修改 / 删除（名下已有手工登记的时段不能删除） |
| GET / POST | /api/manual-readings | 手工监测登记清单（支持 outletId、deviceId、metric、month、status）/ 新增（采样时刻须落在故障/送检时段内，方法、检出限、单位、登记人必填） |
| PATCH / DELETE | /api/manual-readings/:id | 修改（已复核入账的锁定）/ 删除 |
| POST | /api/manual-readings/:id/review | 复核：{action: 通过|驳回, reviewer(必填), reviewNote}；无复核人不许通过 |
| GET / POST | /api/readings | 小时值清单（支持 outletId、deviceId、metric、source(自动/补录/手工)、day、month、limit；手工登记以 source=手工 的同形行并入，带 rowType、复核状态、方法、检出限等取证字段）/ 新增 |
| PATCH / DELETE | /api/readings/:id | 修改 / 删除 |
| GET / POST | /api/reports | 报表清单 / 新建 |
| GET / PATCH | /api/reports/:id | 报表详情（含各排放口的汇总与逐日明细）/ 改状态 |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
