# 污染源在线监测与排污总量核算台

运维与环保岗共用的核算台：录排污单位与排放口、管在线设备、盯小时值、算日平均与总量、对许可量、出报表。

## 运行

```
npm install
npm start
```

默认端口 5260（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：单位数量与生产中数量、排放口数量与运行中数量、设备数量与各状态台数、监测数据条数（自动/补录/手工替代及待复核数）、无效标记条数、报表数量与已上报数量、超标排放口数量、年累计排放量（含其中手工替代分量）与年许可量对照；下面按排放口一行给出本月各指标的月均值、月总量（自动/替代分列）、缺口天数、超标情况。
- **排污单位与排放口**：单位台账（编码、名称、行业、状态、许可证号、许可年起始日）带排放口清单；排放口台账（编码、名称、所属单位、类型、状态、设备数、数据条数），两者都带增改删。
- **在线设备**：设备台账（编号、所属排放口、监测指标、型号、设备状态、校准有效期、数据条数、无效标记条数），带增改删。
- **监测数据**：自动小时值与**手工替代记录同清单区分**（类别、来源、复核状态分开显示，手工行带采样时刻、监测方法、检出限、监测单位、报告编号、采样人、复核人，可按来源与复核状态筛选），支持按排放口、设备、指标、日期与月份筛选，自动读数带单条新增、修改与删除，手工记录走「替代取证」页登记与复核。
- **替代取证**：设备故障/送检时段登记表（设备、原因、起止时刻、登记人，同设备时段重叠拒绝登记）；手工监测记录登记表，缺采样时刻、监测方法（含标准号）、检出限、结果单位、监测单位、报告/原始记录编号、采样人、登记人任一项，或采样时刻不在已登记时段内的，接口拒绝入账；记录须由采样人以外的复核人复核通过后才作为等效值，已复核记录锁定修改/删除（需先退回）。
- **核算与报表**：选定排放口与月份后逐日按「自动 / 手工替代 / 自动+替代 / 缺口 / 停产停用」分类给出明细（自动小时、手工样本数与替代小时、补录小时、日均、限值、判定、当日流量合计、**流量口径或缺口原因**），页面顶部以红色卡片逐日列出缺口原因；汇总给出月均、月总量（自动、替代分列）、有效天数、缺口天数、覆盖率与替代占比、季度总量（含替代分量）与季度许可量、年累计、年许可量、超标情况；报表详情的汇总与逐日明细同样区分自动、替代与缺口。

## 口径（页面上的说明与数字都要与本段一致）

1. **有效小时值**：数据标记为有效、设备状态为「正常」、数值在量程（默认 0 到 500）之内，三条都满足才计入统计；设备处于校准、维护、故障状态，或者数值超量程或为负数的，按无效处理（不计入平均、总量与超标判定），页面要显式标出来。
2. **折算浓度**：`折算浓度 = 实测浓度 × (21 − 基准氧含量) / (21 − 实测氧含量)`，基准氧含量默认 8（可在设置里改）；该时刻没有氧含量读数时按基准氧处理（等价于不折算）。所有平均、总量与超标判定都用折算后的浓度。
3. **日平均**：按小时流量加权，`日均 = Σ(折算浓度 × 该小时流量) / Σ该小时流量`；单日有效小时不足（口径按 18 小时）或者补录小时超过上限（默认 6 小时）的，**该日不计入平均与总量**，页面要写明原因。
4. **补录**：允许用相邻有效值补算缺失小时，补录数据要在页面与结果里与原数据区分开；补录超过单日上限时该日按无效处理，不许把补出来的数当真实监测结果用。
5. **月总量**：`每小时排放量(吨) = 折算浓度(mg/L) × 流量(m³/h) × 1000(升每立方米) / 1e9`，月总量是逐小时按时刻配对累加（浓度与流量必须取同一时刻的那一对）；月平均按有数据且有效的天数平均（分母是有效天数，不是当月天数）。季度总量与年累计用同一套公式逐小时累加，不做任何按天外推。
6. **季度与年**：季度总量按季度内逐小时累加；季度许可量按年许可量乘以该季度实际天数占全年天数的比例分解；年累计按许可年（单位台账里的许可年起始日）累计，跨自然年不重置也不带入其他许可年的数据。
7. **超标判定**：日平均超过限值（COD 100、氨氮 15，可改）**或者**小时值超过限值达到 3 次及以上，都算这个月超标；两项都要在页面上分别给出。
8. **不计入统计的情形**：排污单位处于停产状态、或者排放口处于停用状态的时段，其小时值不计入平均与总量，也不参与超标判定（但要保留可查）。
9. **手工替代取证（设备故障/送检期间）**：
   - **入账依据**：先在「替代取证」登记设备故障/送检时段（设备、原因、起止时刻、登记人，同设备时段不许重叠）；手工监测记录必须落在该设备已登记时段内，且采样时刻、监测方法（含标准号）、检出限、结果单位、监测单位、报告/原始记录编号、采样人、登记人齐全，缺一不可（接口直接拒绝）。记录状态为「待复核 / 已复核 / 复核退回」，复核人不得与采样人为同一人；**只有已复核记录才作为等效值**参与平均与总量，已复核记录锁定修改与删除（更正须先退回）。
   - **替代边界（口径在设置里可改）**：单日有效（自动+替代）不足 18 小时的日子不成立；替代日每个指标手工监测每日不少于 4 次；一次故障/送检连续替代不超过 5 天（第 6 天起即便有合格手工数据也按缺口）；手工替代覆盖小时数不超过当月应测小时数的 80%（超出的替代日按缺口）。凡无已复核手工数据、样本不足、超过连续天数或覆盖比例的时段，一律**按缺口处理**，逐日在页面红色卡片与逐日表显式标出原因（含「有 N 条待复核不能等效」），不许用替代数据把缺口填平、也不做任何按天外推。
   - **取值与配对**：替代期间浓度按当日已复核手工样本均值（氧含量仍按口径 2 折算，无在线氧含量按基准氧不折算）；**流量按口径处理**——优先用同时刻在线流量计实测；在线流量只有部分小时的按当日在线小时均值折全天；完全没有在线流量的，按故障前 7 个有效日的小时平均流量推算，页面逐日注明流量口径（在线实测 / 在线折全天 / 回溯推算）。手工值只承担自动缺测部分的流量，避免与自动小时重复计。
   - **区分要求**：自动数据、补录数据与手工替代数据在清单、逐日、汇总、报表中都按来源、时段、复核状态区分（徽标、行底色、自动/替代吨数分列）；月总量 = 自动分量 + 替代分量，季度与年累计同口径逐小时/逐日累加且自动、替代分列；月平均的分母仍是有效天数（自动日 + 合格替代日）。缺口日既不进平均也不进总量。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/plants | 单位清单（支持 status、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/plants/:id | 详情（含排放口、报表）/ 修改 / 删除 |
| GET / POST | /api/outlets | 排放口清单（支持 plantId、status）/ 新增 |
| PATCH / DELETE | /api/outlets/:id | 修改 / 删除 |
| GET | /api/outlets/:id/summary?month= | 月均、月总量、季度总量与许可、年累计、超标情况、设备清单 |
| GET | /api/outlets/:id/daily?month=&metric= | 逐日明细（有效小时数、补录小时数、日均、限值、是否超标、流量合计） |
| GET | /api/outlets/:id/exceedance?month=&metric= | 超标判定（超标天数、超标小时数、是否超标、月均） |
| GET / POST | /api/devices | 设备清单（支持 outletId、metric、status）/ 新增 |
| PATCH / DELETE | /api/devices/:id | 修改 / 删除 |
| GET / POST | /api/readings | 小时值清单（自动+手工替代合并，支持 outletId、deviceId、metric、day、month、source、reviewStatus、limit；source=手工替代 只看手工记录）/ 新增自动读数 |
| PATCH / DELETE | /api/readings/:id | 修改 / 删除 |
| GET / POST | /api/outages | 设备故障/送检时段清单（支持 deviceId、outletId、reason、from、to）/ 登记（同设备重叠返回 OUTAGE_OVERLAP） |
| PATCH / DELETE | /api/outages/:id | 修改 / 删除时段 |
| GET / POST | /api/manual-records | 手工监测记录清单（支持 outletId、deviceId、metric、day、month、reviewStatus）/ 登记（依据不全 400、不在登记时段内 409） |
| GET / PATCH / DELETE | /api/manual-records/:id | 详情 / 修改（已复核锁定）/ 删除（已复核锁定） |
| POST | /api/manual-records/:id/review | 复核动作 `{"action":"approve|reject","reviewedBy":"..."}`，复核人不得等于采样人 |
| GET / POST | /api/reports | 报表清单 / 新建 |
| GET / PATCH | /api/reports/:id | 报表详情（含各排放口的汇总与逐日明细，自动/替代/缺口分列）/ 改状态 |

设置项除原有口径外新增：`validHoursPerDay`（单日有效小时门槛，18）、`manualMinSamplesPerDay`（替代日手工最少次数，4）、`manualMaxConsecutiveDays`（连续替代最长天数，5）、`manualMaxCoveragePercent`（替代覆盖率上限，80）、`manualFlowLookbackDays`（流量缺失回溯天数，7）。

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
